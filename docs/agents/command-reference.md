# Command Reference

The on-demand command catalogue for the root [Agent Guide](../../AGENTS.md#commands). The everyday commands — build, test, e2e, lint, format, AI commit, AI PR, OpenAPI sync, Prisma, and `yarn gates:run` — live there and are not restated here. Each command is documented once: add a new gate, measurement, or tool command to this file, not to `AGENTS.md`.

## Release

- Release (cut branch): `yarn release:cut --version vX.Y.Z --push --notes-file RELEASE_NOTES.md`.
- Release (tag after production deploy): `yarn release:tag --version vX.Y.Z --push`.
- Release dry-run (preview only): `yarn release:cut --version vX.Y.Z --dry-run`.

## Sub-agents and Skills

- Sub-agent sync check: `yarn agents:sync:check`.
- Sub-agent sync apply: `yarn agents:sync`.
- Sub-agent model/catalog audit: `yarn agents:models:audit`.
- Sub-agent model audit contracts (retirement-table reader): `node --test tools/scripts/lib/model-retirements.test.ts`.
- Sandcastle loop usage summary: `yarn agents:usage:report`.
- Committed Upstream Brief reports: `yarn upstream:briefs:check` (re-validates every structured `*.json` report committed under the brief directory, checking each local citation against the commit the report itself records; `yarn upstream:briefs:test` covers the contract, renderer, CLIs, and ledger under `.agents/skills/upstream-brief`; the checker's own suite runs in `yarn tools:test`). See [ADR 0084](../adr/0084-an-upstream-brief-is-anchored-to-what-is-installed-and-accepted-on-checked-evidence.md) and [ADR 0018](../adr/0018-upstream-brief-portable-instruction-audit.md); shape and memory in [REPORT.md](../../.agents/skills/upstream-brief/REPORT.md), [LEDGER.md](../../.agents/skills/upstream-brief/LEDGER.md), and [SKILL.md](../../.agents/skills/upstream-brief/SKILL.md).

## Code review

- Review Tier classifier: `yarn review:tier:check --base <sha> --head <sha> [--author <login>]` (computes `review:auto|agent|human` from the diff, the Nx graph, and `tools/config/review-tier-paths.json`; `yarn review:tier:replay` re-tiers the last 200 merged Pull Requests for threshold tuning). See [ADR 0070](../adr/0070-a-review-tier-is-a-fact-about-the-diff-and-a-gate-tier-is-a-decision-about-the-work.md).
- Code review concurrency check: `yarn review:concurrency:check` (asserts every trigger the `Code Review` workflow's `context` job refuses is also steered out of the review's concurrency group; `--print` shows both expressions, `node --test tools/scripts/check-review-concurrency.test.ts` covers it). See [ADR 0115](../adr/0115-a-concurrency-group-agrees-with-the-job-it-cannot-see.md).
- Review checklist check: `yarn review:checklist:check` (asserts [`docs/review/REVIEW_CHECKLIST.md`](../review/REVIEW_CHECKLIST.md) agrees with `tools/config/review-obligations.json` on ids, order, and fields; `--print` shows both sides).
- Obligation answer check: `yarn review:obligations:check <worklist.json> <answers.json>` (asserts every cited answer field matches the tree at the reviewed head and that a required defect was actually raised as a finding; `yarn tools:test` covers it). See [ADR 0078](../adr/0078-a-citation-that-does-not-match-its-source-is-a-fact-about-the-pipeline.md) (ADR 0073 gates on the ground it establishes).
- Rule catalogue check: `yarn review:rules:check` (asserts `tools/config/review-rules.json` agrees with the finding contract, the obligations catalogue, and the ids each axis's brief file beside [the code-review skill](../../.agents/skills/code-review/SKILL.md) offers its sub-agent, and that the two briefs carry the same shared block; `--print` lists the catalogue, `yarn tools:test` covers the loader). See [ADR 0071](../adr/0071-a-finding-blocks-only-on-evidence-and-a-verdict-is-computed-never-written.md).
- Reviewer tool allowlist check: `yarn review:allowlist:check` (asserts every command the code-review skill or [the Review Checklist](../review/REVIEW_CHECKLIST.md) instructs is permitted by `.github/actions/code-reviewer/action.yml`'s `--allowedTools` and not intercepted by an `ask`/`deny` rule in tracked `.claude/settings.json`, and that every path-scoped file grant there is anchored and on a tool Claude Code consults; `--print` shows every entry and rule, `node --test tools/scripts/check-review-tool-allowlist.test.ts` covers the matcher). See [ADR 0099](../adr/0099-a-project-ask-rule-is-a-refusal-in-a-headless-run.md), [ADR 0118](../adr/0118-a-file-grant-is-anchored-where-the-session-started.md), and [the run-45 research brief](../research/2026-09-10-the-answer-sheet-is-inert.md).
- Code review golden set: `yarn review:golden:check` (asserts `tools/config/review-golden-set.json` is well-formed and reachable from `main`, and matches the replay's trigger, tier, and pre-score obligation-gate rules; `yarn review:golden:score --case <id> --normalized <file>` scores one replay). See [ADR 0109](../adr/0109-a-golden-replay-runs-on-a-schedule-and-on-request.md), [ADR 0102](../adr/0102-a-golden-replay-reviews-the-case-tree-with-the-pull-requests-harness.md), [ADR 0072](../adr/0072-a-golden-case-earns-its-replay-frequency.md), [ADR 0116](../adr/0116-a-golden-case-stands-on-its-catch-rate-over-its-last-ten-scored-runs.md), [ADR 0074](../adr/0074-a-gate-suppresses-a-finding-only-if-something-runs-it.md), and [ADR 0101](../adr/0101-a-replay-whose-answer-sheet-fails-its-check-measured-nothing.md); results are kept current in [`docs/review/golden-replay-results.md`](../review/golden-replay-results.md).
- Code review escaped-defect rate: `yarn review:escaped:measure [--days 60]` (of the Pull Requests the reviewer passed, what fraction a later fix names as root cause; `yarn tools:test` covers the attribution parser). Not a gate; opt-out in `tools/config/gate-coverage-optout.json`. See [ADR 0077](../adr/0077-an-escaped-defect-is-one-the-reviewer-saw-and-passed.md); kept current in [`docs/review/escaped-defect-rate.md`](../review/escaped-defect-rate.md).
- Fix attribution check: `yarn fix:attribution:check --base <sha> --head <sha> --branch <ref> [--title <text>]` (asserts a fix's commits carry `Introduced in #<pull request>` or a named `unknown` reason; `node --test tools/scripts/check-fix-attribution.test.ts` covers it). See [ADR 0100](../adr/0100-a-fix-names-what-introduced-it-in-its-commits.md).
- Code review effective-false-positive rate: `yarn review:noise:measure [--days 30]` (per rule, the share of findings raised and still unaddressed on the next push; `--save-gather` persists the 30-day evidence window; `yarn tools:test` covers the classes, marker, and budget). Not a gate; opt-out in `tools/config/gate-coverage-optout.json`. See [ADR 0079](../adr/0079-an-effective-false-positive-is-a-finding-nobody-acted-on.md); kept current in [`docs/review/effective-false-positive-rate.md`](../review/effective-false-positive-rate.md).
- Code review report contract: `yarn review:validate <report.json> --out <normalized.json> [--previous <normalized.json>] [--facts <run-facts.json>] [--worklist <obligations.json>]` rejects or normalizes a `/code-review` report, computes its verdict, and carries each finding's id forward from the previous report; `yarn review:render <normalized.json>` renders the two-section Markdown; `yarn tools:test` runs the contract tests. See [ADR 0071](../adr/0071-a-finding-blocks-only-on-evidence-and-a-verdict-is-computed-never-written.md).
- Code review run facts: `node tools/scripts/review/read-transcript-facts.ts <execution-file> --out <run-facts.json> [--index CODING_STANDARDS.md]` reads a reviewer transcript for the standards documents the Standards sub-agent opened, the commands the sub-agents ran, the session's duration, token figures, model and Claude Code CLI version, and whether each dispatch was the skill's template; `yarn review:validate --facts <run-facts.json>` overwrites the report's own claims with them and judges the run: no sub-agent reading an axis's brief, or a reported finding no sub-agent returned, is recorded as a failure that fails `Agent Review Ran` and voids a golden replay, while an unopened `CODING_STANDARDS.md`, a dispatch off the template, or a transcript or reply that cannot be read tightens the Review Tier one step. The reader itself gates nothing; a transcript it cannot read is recorded as unknown, never as an empty list. `yarn tools:test` covers both against fixtures cut from real transcripts. See [ADR 0123](../adr/0123-a-review-reports-facts-about-its-own-run-are-read-from-the-transcript.md).
- CI code review: `.github/workflows/code-review.yml` runs the `/code-review` skill as two checks — `Agent Review Ran` (pipeline facts, eligible to be required) and `Agent Verdict` (a judgment on the diff, permanently advisory). Triggers automatically per the `CODE_REVIEW_MODE` repository variable (`CODE_REVIEW_ENABLED=false` disables it), or on demand via the `agent-review` label, a `/code-review` comment, or `workflow_dispatch`; needs `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY`. See [ADR 0070](../adr/0070-a-review-tier-is-a-fact-about-the-diff-and-a-gate-tier-is-a-decision-about-the-work.md) item 6, [ADR 0071](../adr/0071-a-finding-blocks-only-on-evidence-and-a-verdict-is-computed-never-written.md), [ADR 0073](../adr/0073-a-required-check-is-a-fact-about-the-pipeline-not-a-judgment-about-the-diff.md), [ADR 0078](../adr/0078-a-citation-that-does-not-match-its-source-is-a-fact-about-the-pipeline.md), and [the token-scoping research brief](../research/2026-09-07-resolve-review-thread-token.md).

## Dependencies

- npm audit on `main`: CI audits a pull request only when it changes dependencies, and audits every push to `main`. A red `Secure Install Review` on `main` is how a new advisory surfaces: find the open issue titled `[automation] npm audit is failing on main`, bump the listed packages, and run the `dep-sync` Skill. Do not make the audit run on every pull request. `node --test tools/scripts/lib/npm-audit-issue.test.ts` covers the issue logic in `tools/scripts/lib/npm-audit-issue.ts`. See [ADR 0124](../adr/0124-the-npm-audit-runs-on-main-and-a-failure-there-is-one-tracked-issue.md) and [the supply chain plan](../SECURITY/Dependency-Supply-Chain-Security-Plan.md).

## Gate infrastructure

- Tooling suite runner: `yarn tools:test` (one `node --test` process over every `*.test.ts` under `tools/scripts`, about 34s for the full set; CI's `Test` job runs this in place of the per-suite scripts and steps it replaced — it is the only runner `gates:coverage:check` counts, so a suite is wired by existing; run one suite in isolation with `node --test <file>`; deliberately not a Declared Nx Target, see [ADR 0082](../adr/0082-nx-targets-are-inferred-and-a-declared-target-is-migration-debt.md) and [ADR 0083](../adr/0083-a-declared-target-is-debt-only-on-an-executor-nx-deprecated.md)). See [ADR 0135](../adr/0135-tooling-scripts-are-typescript-run-by-node-and-tested-by-node-test.md).
- Tooling suite runner, staged selection: `yarn tools:test:staged` (Husky's pre-commit selection — the suite staged directly, plus the suite paired by name with each staged script, `check-x.ts` -> `check-x.test.ts`; a commit with no staged `tools/scripts` file runs nothing here. The decision is pure in `tools/scripts/lib/tools-test-selection.ts`; `node --test tools/scripts/lib/tools-test-selection.test.ts` covers it). See [ADR 0135](../adr/0135-tooling-scripts-are-typescript-run-by-node-and-tested-by-node-test.md).
- Wired-gate check: `yarn gates:coverage:check` (the Meta-Gate — asserts every `tools/scripts/check-*.ts` is invoked by a hook or workflow, matched by exact script name, including through the aggregate; rejects any `check-*.mjs` by name; and asserts `tools:test` is wired and its glob reaches every `*.test.ts` Contract Suite under `tools/scripts`; an intentional non-gate or a deliberately unrun suite needs a written-reason entry in `tools/config/gate-coverage-optout.json`; `node --test tools/scripts/lib/gate-coverage.test.ts tools/scripts/check-gate-coverage.test.ts` covers both rules). See [ADR 0043](../adr/0043-gates-assert-facts.md) and [ADR 0135](../adr/0135-tooling-scripts-are-typescript-run-by-node-and-tested-by-node-test.md).
- Heavy gate trigger resolver: `node tools/scripts/ci/resolve-gate-triggers.ts <baseSha> <headSha>` (or `--all`) — prints one GitHub Actions `run_<suite>=true|false` line per heavy suite in `tools/config/gate-triggers.json`, `run_all` first, for CI's `Setup Affected Context` to append to `$GITHUB_OUTPUT`. A shared-input change, a push (`--all`), and any error it can describe all set every flag; a config it cannot parse exits 2 and the workflow writes `run_all=true` instead. Not a gate; the decision is pure in `tools/scripts/lib/gate-triggers.ts`, and `node --test tools/scripts/ci/resolve-gate-triggers.test.ts tools/scripts/ci/gate-trigger-workflow.test.ts` covers the resolver and the workflow wiring it feeds. See [ADR 0140](../adr/0140-a-heavy-assertion-gate-is-path-gated-and-a-covering-gate-is-a-trigger-superset.md).
- Actions cache cleanup: `node tools/scripts/ci/prune-actions-caches.ts --closed-pull-request <n>` or `--prune-ref refs/heads/main [--keep-key <key>]...`, plus `[--repository <owner/name>] [--dry-run]` — deletes the GitHub Actions cache entries nothing can restore from, keeping the repository under GitHub's 10 GB limit. `.github/workflows/cache-cleanup.yml` is the only caller and needs `actions: write`; run it by hand with `workflow_dispatch` and its `dry_run` input rather than locally, since it reads `GH_TOKEN`. It never deletes the newest entry of a Cache Family, and a listing it cannot read deletes nothing and exits 2 — the fallback here is always to delete less. A read-only token (a fork's or Dependabot's on a closed pull request) warns and exits 0. Not a gate; the selection is pure in `tools/scripts/lib/actions-cache-cleanup.ts`, and `node --test tools/scripts/lib/actions-cache-cleanup.test.ts tools/scripts/ci/prune-actions-caches.test.ts tools/scripts/ci/cache-cleanup-workflow.test.ts` covers the selection, the CLI, and the workflow shape it feeds.
- Covering Gate trigger-superset check: `yarn covering-gates:check` (asserts that a path-gated Covering Gate's trigger globs cover every trigger path of a review obligation naming it, and that a Covering Gate named only through a non-path trigger is not path-gated; it does not assert that a suite in the config is some obligation's Covering Gate, nor that the gate is invoked anywhere — that is `gates:coverage:check`; `--print` lists the gate/glob pairs compared; reached by `yarn gates:run`; `node --test tools/scripts/lib/covering-gates.test.ts tools/scripts/check-covering-gates.test.ts` covers it). See [ADR 0140](../adr/0140-a-heavy-assertion-gate-is-path-gated-and-a-covering-gate-is-a-trigger-superset.md) and [ADR 0074](../adr/0074-a-gate-suppresses-a-finding-only-if-something-runs-it.md).
- Checker contract-coverage check: `yarn checker-contracts:check` (asserts every `check-*.ts` carries a contract suite proving it fails on the drift its header claims to catch, or is named in the shrink-only baseline `tools/config/checker-contract-baseline.json` — no written-reason opt-out; `node --test tools/scripts/check-checker-contracts.test.ts` covers it). See [ADR 0085](../adr/0085-an-artifact-states-no-claim-it-does-not-assert.md).
- Tooling `.ts` suppression check: `yarn ts-suppressions:check` (asserts no `tools/scripts` `.ts` file carries `@ts-nocheck` or `@ts-ignore`, and that every `@ts-expect-error` carries a written reason on the same line; `node --test tools/scripts/check-ts-suppressions.test.ts` covers it). See [ADR 0135](../adr/0135-tooling-scripts-are-typescript-run-by-node-and-tested-by-node-test.md).
- Tooling `.mjs` check: `yarn tools:mjs:check` (fails naming any `.mjs` file at any depth under `tools/scripts`, `node_modules` excepted, so the retired untyped form cannot come back; it does not assert that every file there is `.ts`, since shell, JSON, and config files belong there too; reached by `yarn gates:run`; `node --test tools/scripts/check-tools-mjs.test.ts` covers it). See [ADR 0135](../adr/0135-tooling-scripts-are-typescript-run-by-node-and-tested-by-node-test.md).
- Git-fixture environment isolation contracts: `node --test tools/scripts/lib/git-environment.test.ts` (fails any `tools/scripts` suite that runs `git init` without calling `isolateGitEnvironment()` from `tools/scripts/lib/git-environment.ts` at module top level, and runs one such suite under a hook-shaped `GIT_DIR` from a linked worktree to prove the outer repository's branch and config are unchanged; a hook's inherited `GIT_DIR` otherwise sends fixture commits into the hook's repository and can set `core.bare = true` in the primary checkout; CI runs it).
